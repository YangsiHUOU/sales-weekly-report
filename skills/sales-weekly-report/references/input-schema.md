# 输入结构

## Excel 工作表

- `02_基本信息`：公司名称、周报名称、刊期、统计起止日期、金额单位、发布渠道、头版主题、示例标识。
- `03_团队业绩`：团队/部门、本周保费、周目标、月度累计、上周保费、备注。
- `03A_机构业绩`：机构名称、本周保费、备注；用于生成机构 TOP3。
- `04_个人业绩`：姓名、所属团队、本周保费、出单数、重点业务/亮点、是否展示。
- `05_每日业绩`：日期、星期、当日保费、当日目标。
- `06_一线有话说`：姓名、部门、岗位、原始文字、希望强调的重点、照片文件名、是否展示。
- `07_团队建设荣誉`：兼容保留的输入工作表，内容输出到海报“公司动态”栏目；填写类型、标题、日期、地点、通知/材料原文、照片文件名、荣誉对象、是否展示。
- `08_图片清单`：文件名、对应栏目、人物/活动、图片说明、建议裁切、是否可公开到公司群。
- `09_动态检索配置`：公司、行业、地域关键词和来源偏好。

金额统一使用“万元”，百分比不要手工写入数据表。排行、合计、达成率和环比由生成器计算。

长图头版不展示统计日期范围；统计起止日期仍必须填写，用于限定行业动态检索窗口。行业动态位于头部下方第 01 栏，海报不展示来源名称，但审计 JSON 必须保留来源与 URL。业绩通报为第 02 栏，仅展示本周走势及团队、机构、个人三个 TOP3，不展示 KPI 合计卡。

叙述性正文可以用换行表示自然段，但不要插入空白行；渲染器为每个自然段应用首行 2 字符缩进。标题中的换行用于人工控制语义分行，不应用首行缩进。

## editorial.json

```json
{
  "headline": "深耕一线，聚力业务突破",
  "news": [
    {
      "tag": "监管动态",
      "date": "2026-07-17",
      "title": "标题",
      "summary": "160—200字深圳市场事实摘要，交代背景、关键数据或变化及保险业务相关风险逻辑",
      "source": "来源名称",
      "url": "https://example.com/source"
    }
  ],
  "frontline": {
    "show": true,
    "photo": "人物照片.jpg",
    "quote": "提炼后的引语",
    "body": "润色后正文"
  },
  "team_building": {
    "photo": "现场照片.jpg",
    "title": "通报标题",
    "subtitle": "会议或培训名称",
    "body": "润色后正文"
  },
  "honor": {
    "title": "荣誉名称",
    "body": "获奖对象与原因"
  }
}
```

`news` 正式生成时必须为本周重新检索的 3 条深圳市场内容。每条 `date` 都必须是来源页面标注的正式发布日期，并位于 Excel“统计开始日期”至“统计结束日期”之间；周五生成时即当周周一至周五。搜索引擎抓取日期、旧闻转载日期和事件发生日期不能代替发布日期。任何一条超期都应停止生成，不得用上周、上月或更早内容补位。不要沿用上期内容，也不要设置 `insight` 或“销售启示”。没有荣誉时省略 `honor`。

没有一线分享时设置 `"frontline": {"show": false}`。照片优先读取编辑稿的 `photo`，否则读取 Excel 对应文件名；未提供现场照片时省略 `photo`，不设置虚构路径。

团队/机构表允许只填写已筛选的排行候选。此时每日保费仍为公司全量走势，不能用候选团队合计替代，也不能将周保费平均拆成每日数据。
